# Улучшения ThreadsGo тремя субагентами

2 октября 2026. Задачи разделены: путь клиента до первого поста, дизайн и доступность, надёжность браузерного подключения. Родитель свёл изменения, исправил серверное редактирование/перегенерацию и восстановление общего стиля. Это законченный выпуск конкретных улучшений, а не заявление об отсутствии всех ошибок.

## Что изменилось

- Кабинет предлагает продолжить проект, где нет рабочего профиля или ближайшего поста. Обзор проекта показывает один следующий шаг по реальному состоянию; идеи и пустое расписание дают рабочие переходы к настройке.
- Черновик можно редактировать; все части цепочки имеют отдельные поля и проверку 500 символов. Ошибка сохранения оставляет редактор открытым. Во время сохранения ввод заблокирован, чтобы не потерять новые правки.
- Серверное изменение текста сохраняет статус: draft не становится queued, failed/cancelled не возобновляются сами. Перегенерация не создаёт промежуточную задачу queued. Условное обновление не перезаписывает пост, если его текст/статус уже изменились; неподтверждённая публикация требует сверки.
- Вход читабелен в светлой теме; мобильное меню главной содержит тарифы, вход, регистрацию, блог и обновления. Escape возвращает фокус. Навигация проекта отмечает один текущий раздел; кнопка темы имеет область нажатия 44 px, предупреждения тёмной темы различаются цветами.
- Cookie-плашка компактнее, при коротком экране прокручивается. Аналитика по-прежнему запускается только после разрешения; Вебвизор не включён.
- Несохранённый общий стиль сохраняется в sessionStorage конкретного пользователя на срок до суток. При возвращении предлагается восстановление; действующий стиль меняется только после сохранения. При недоступном хранилище редактор продолжает работать. Это восстановление в текущей вкладке, не серверная история версий.
- Окно Threads не выполняет просроченные/отменённые команды, показывает оставшееся время, лучше обрабатывает быстрый ввод и закрытие. Не считает произвольный публичный /@username доказательством владельца; при неизвестной локали интерфейса безопасно отказывает.
- Цель first_post_queued отправляется один раз в рамках сохранённого браузерного состояния пользователя и только при queued со временем публикации. Это не серверная сквозная уникальность между устройствами.

## Проверки

Три новых целевых сценария API редактирования прошли; вместе с импортированным существующим fixture автоматически выполнились 14 сценариев, все прошли. Четыре проверки окна Threads прошли у субагента. TypeScript и production build клиента/SSR/пререндер прошли. Субагент проверил 320 px и обе темы: меню, вход/регистрация, состояние Telegram, навигацию и отсутствие горизонтального переполнения. Короткая проверка рендеринга проверила четыре состояния пути клиента. Родитель отдельно просмотрел согласованное состояние проекта и светлый вход. SEO-проверка применяется перед выпуском.

## Что не подтверждено этим выпуском

Реальные входы владельцев Threads, отправка постов, оплаты и поступление новых рекламных конверсий не выполнялись. При полном зависании конструктора Chrome пилотное окно может оставаться занятым до возврата драйвера или перезапуска; после получения драйвера запросы ограничены по времени. Пока одновременно доступно одно браузерное окно, обновление существующей сессии остаётся через импорт.

Реклама не запущена; eLama и аккаунт Директа созданы, деньги не списывались. Российский узел хранения данных и уведомления РКН требуют отдельной работы. Нельзя называть текущую немецкую инфраструктуру полностью соответствующей 152-ФЗ или гарантировать отсутствие блокировок Meta.
