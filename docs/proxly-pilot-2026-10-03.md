# Proxly Residential: безопасный пилот ThreadsGo

Дата: 3 октября 2026. Пакет оператора: 10 ГБ, общий для ThreadsGo и ThreadsClinic.
Никаких секретов в этом документе нет. Действующие пользователи автоматически не мигрируют.

## Подключение и изоляция

- HTTP `proxly.ru:8080`, NL, логин `<access-login>-country-nl-session-<id>-time-30`.
- Clinic владеет ID 1–10. ThreadsGo выделяет ID от 11 через долговечный атомарный счётчик;
  удаление аккаунта не возвращает ID в пул. Проверки двух соединений тоже резервируют ID.
- Привязка аккаунта хранится в БД. Повторная настройка/возобновление сохраняет ID.
  Это не обещание сохранения внешнего IP: sticky около 30 минут, после срока адрес меняется.
- Старый порт Proxymarket сохраняется для отката. Новый провайдер выбирается явно по одному аккаунту.
- Общий конфиг и снимок подключения аккаунта зашифрованы Fernet; чтение API не возвращает реквизиты.
  Обновление общего пароля не меняет работающие аккаунты: примените его отдельно после завершения операций.
- Отдельные Chrome-профили/cookies по account ID; OS-блокировка профиля действует и между subprocess.
- При новом входе через окно полный временный профиль переносится в папку аккаунта после закрытия Chrome;
  сохраняются cookies, local storage и параметры окна 1024×768. Ошибка переноса откатывает создание аккаунта,
  существующие папки не перезаписываются. Старые импортированные профили используют прежние настройки.
  Это стабильное окружение сервиса, а не гарантия неизменного аппаратного отпечатка: версия Chrome обновляется.
- Один worker на аккаунт, последовательные операции. Разные аккаунты используют общий browser semaphore.
  Реальная параллельность ограничена MAX_CONCURRENT_BROWSERS и мощностью машины, а не числом Session ID.
  Сейчас лимит не увеличивается автоматически: сначала замерить RAM/CPU пилота.

## Очередь и сбои

- Прокси и доступ перечитываются после ожидания browser semaphore, непосредственно перед IP-проверкой.
  Простаивающие аккаунты не отправляют периодические IP-запросы. Проверки админки требуют явного действия.
- IP проверяется через прокси: HTTPS ipify, ограничение ответа 512 байт, таймаут, без redirects/system proxy.
- Proxy routing задан Chrome явно; если auth extension не работает, будет ошибка прокси, не direct fallback.
- При ошибке выполняется ограниченный backoff вне browser semaphore; серия отказов ставит профиль на паузу.
- Перед действиями проверяется срок оплаченного/подарочного доступа; legacy подписки без даты сохраняют прежнее поведение.
  Очередь сохраняется, а не удаляется; после продления применяется та же привязка Session ID.
- Проверка Meta/истёкшие cookies требуют ручного восстановления. Sticky или сохранённый профиль не исключают ограничений.
- После неизвестного результата отправки задача получает `publication_confirmation_pending` и не публикуется повторно.
  Нужно сверить профиль/ссылку на публикацию. Смена IP во время отправки не является разрешением на слепой повтор.

## Трафик и стоимость

- Блокировка video/audio уже была; изображения, JS, стили и шрифты оставлены для работоспособности входа.
- Chrome performance `Network.loadingFinished.encodedDataLength` даёт **неполную оценку** наблюдаемых ответов.
  Возможны потеря событий/недоступная телеметрия; нет исходящих запросов/TLS/CONNECT/прочего overhead.
  Неточные данные не используются как точный баланс или лимит оплаченного пакета.
- `proxy_usage_events`: account/owner/provider/service/source/status/bytes/time.
  Дашборд агрегирует аккаунты, пользователей и сервис ThreadsGo. Расход Clinic пока неизвестен:
  для него нужен отдельный экспорт/интеграция с метриками Clinic либо API провайдера.
- По заявленному тарифу 10 ГБ за 1120 ₽: 112 ₽/ГБ против приблизительно 400 ₽/ГБ,
  снижение ставки на 72%. Формула оценки: байты / 1e9 × 112.
  При 10 МБ это 1,12 ₽; при 100 МБ — 11,20 ₽; при 1 ГБ — 112 ₽.
  Это арифметические сценарии, не измеренный расход аккаунта и не стоимость в месяц.
- Реальный расход браузерного задания и месяц работы определяются пилотом и сверкой с кабинетом Proxly.
  Единица GB/GiB и правила округления/учёта провайдера не подтверждены.

## Админка и порядок пилота

`/app/admin/proxies` доступна только ADMIN_TG_ID (или операторскому API-токену),
обычный одобренный пользователь сервиса не является администратором.

1. Сохранить логин/пароль через защищённую форму. Поля скрыты и очищаются после сохранения.
2. «Проверить две сессии без входа»: два параллельных HTTP-клиента, по два небольших GET,
   ограниченное время, без Threads/cookies/изменения существующих аккаунтов. Результаты IP обезличены.
   Этот короткий тест не доказывает сохранение IP на 30 минут, независимость или эксклюзивность адресов.
3. Выбрать согласованный собственный аккаунт `arsevenars`. Подключение ставит профиль на паузу.
4. Проверить соединение и сохранённый вход. При ошибке сохранить паузу или откатить прокси;
   чужие аккаунты не переключать. При необходимости пройти проверку Meta самостоятельно.
5. Сравнить вход в двух запусках, включая интервал больше sticky TTL. Затем согласовать один
   тестовый пост и сверить результат. Не публиковать пробные посты без одобрения автора.
6. После успеха включить работу профиля. Проверять ошибки и расход; расширять постепенно.

### Первая реальная проверка без Threads

3 октября: с production-сервера два одновременных HTTP-клиента, ID 11 и 12,
по два HTTPS-запроса ipify. Все четыре ответа успешны; внутри короткого наблюдения
каждая сессия сохраняла IP, а между сессиями адреса различались. Время 7,69 с,
ответы суммарно 50 байт. Полный оплачиваемый трафик неизвестен; это не расход браузера.
ID 11/12 после выпуска зарезервированы счётчиком и не назначаются клиентам.
Ни одно действие в настоящем Threads-аккаунте этой проверкой не выполнялось.
Результат не доказывает эксклюзивность IP, TTL 30 минут или стабильность публикаций.

## Пока не подтверждено провайдером

- Поведение при потере резидентного узла: ошибка, смена IP или иной fallback; отсчёт/reset sticky TTL.
- Фактические лимиты соединений и Session ID (публичное «без лимита потоков» не проверено нагрузкой).
- Доступность API статистики по Session ID/сервисам и точного остатка общего пакета.
- Дополнительные платежи/округление/условия общего backend подключения для двух сервисов.
- Оферта запрещает передавать реквизиты третьим лицам без согласия поставщика. Мы реквизиты клиентам
  не выдаём; разрешение именно на общий backend нескольких сервисов всё равно нужно уточнить.
- Работа настоящего Threads-аккаунта после смены страны/IP и между браузерными запусками.
