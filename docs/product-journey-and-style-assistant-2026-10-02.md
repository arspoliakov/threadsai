# Структура продукта и помощник стиля — 2 октября 2026

## Что просмотрено

Карта активных маршрутов frontend/src/App.tsx, общая и проектная навигация,
создание проектов, общий стиль, подсказки первого запуска, обзор и настройки
проекта, профили и очередь. На сервере: маршруты проектов/промптов, проверки
владельца и подписки, сборка системных инструкций и существующий клиент нейросети.
Это целевой аудит пути клиента и связанных операций, а не заявление об отсутствии
всех возможных ошибок в каждой части проекта.

## Внедрено

Помощник доступен при создании проекта и в разделе «Стиль». Три шага: тон и лицо
автора; плотность текста, юмор и отношение к продажам; необязательные ограничения
и образец текста. Образец передаётся для манеры, а не переноса его темы или фактов.
Пользователь видит редактируемый результат. Кнопка «Использовать этот стиль»
только переносит его в редактор. Затем требуется сохранить стиль или создать проект.
Общий стиль действует на все проекты; контекст и конкретные настройки продаж
каждого проекта задаются отдельно и имеют приоритет для коммерческих призывов.
Генерация не гарантирует идеальное выполнение каждой инструкции: текст нужно проверить.

Используется существующая модель и провайдер для постов, без нового ключа и зависимости.
Endpoint POST /api/v1/prompts/global/assist требует авторизацию и активный доступ,
ограничен 3 запросами в минуту и 20 в день на пользователя, одним запросом одновременно
на пользователя и двумя одновременно на процесс. Общий таймаут 40 секунд,
максимум 1800 выходных токенов, автоматических повторных платных запросов нет.
Лимиты и блокировка работают в памяти одного процесса — текущая production-конфигурация
имеет одного worker. При масштабировании перенести их в общее хранилище.
Ответы не сохраняются в БД и не отправляются в аналитику; образец и ограничения
передаются текущему провайдеру нейросети. В интерфейсе есть пояснение.

PUT /api/v1/prompts/global/style заменяет активный VIRALITY-стиль только владельца,
сохраняя историю и другие типы инструкций. При создании проекта выбранный стиль и
сам проект сохраняются одной транзакцией. Владелец проекта записывается до первого commit.
Добавлен явный приоритет авторского тона над общими рекомендациями разговорной подачи;
JSON, ограничения длины, стоп-слова и безопасность бренда остаются обязательными.

Форма создания проекта прокручивается на телефоне, удерживает клавиатурный фокус,
закрывается Escape, блокирует прокрутку фона и сохраняет данные при ошибке.
После успеха открывается созданный проект. Исправлен выбор текущего стиля по типу:
раньше первым мог оказаться formatting-промпт вместо virality.

Исправлено ожидание запросов в создании/удалении проекта, привязке/отвязке/удалении
профилей и отмене/немедленном запуске публикации: toast.promise возвращает идентификатор
уведомления, поэтому ожидать нужно сам API promise. События успеха и обновления экрана
теперь выполняются после ответа сервера.

## Следующие улучшения по приоритету

1. Пробный черновик без подключения Threads. Сейчас trigger-generation требует рабочий
   профиль и ставит результат в расписание. Нужен отдельный draft-only endpoint с
   подпиской и лимитом: не связывать его с публикацией, явно показывать «не публикуется».
   Это даст новичку увидеть свой голос до сложного подключения cookies.
2. Помощник контекста проекта: три вопроса «Что предлагаете?», «Кому?», «Какие проблемы
   решаете?» и короткое редактируемое описание. Общий стиль уже вынесен отдельно;
   второй помощник должен заполнять только проектные поля.
3. Проверка первого поста перед включением автоматического расписания. Сейчас ручная
   генерация с аккаунтом ставит текст в очередь. Отдельное согласование первого
   черновика и явное включение автопубликаций снизят неожиданные публикации.
4. Показывать следующий незавершённый шаг и время до первого результата вместо
   длинного вступительного тура. Чек-лист уже есть; важнее вести к действию,
   чем добавлять ещё одно модальное обучение.
5. Продолжать измерять новый путь по реальным событиям: проект → проверенный профиль →
   черновик → запрос публикации → подтверждённая публикация. Для помощника отправляются
   style_assistant_started/generated/applied без ответов пользователя; отдельные цели
   в Метрике ещё не созданы. Старые квартальные показатели нельзя считать новой когортой.

## Проверка

Три целевых серверных сценария: доступ/лимиты/ошибки и отсутствие сохранения при preview;
владелец и атомарное создание проекта со стилем; откат несохранённой транзакции и
явное сохранение общего стиля. Проверяются соседние пользователи и сохранение иных
типов инструкций. Полный прогон десятков тестов не выполнялся.

Реальный запрос к существующей нейросети на нейтральной анкете вернул 1713 символов.
Интерфейс проверен локально на компонентах production-кода: три шага, редактируемый
результат, перенос без автоматического сохранения, мобильная форма 390×844 без
горизонтального переполнения. Для UI использован локальный демонстрационный ответ из
этой реальной генерации; покупок, изменений клиентских данных и действий в Meta не было.
