# Проверка новинок и помощник проекта — 3 октября 2026

## Область работы

Три субагента проверили серверную логику студии, согласование и ручную генерацию, затем отдельно интерфейс и работу времени. Root интегрировал изменения и проверил путь в изолированном локальном кабинете. Проверены новые черновики, перенос, ИИ-редактор, план недели, календарь, согласование, повторные запросы и создание проекта. Это целевой аудит новинок, не гарантия отсутствия ошибок во всём сервисе или блокировок Meta.

## Исправлено

- Журнал studio_requests хранит резерв бесплатного кредита и результат генерации атомарно. Ошибки освобождают кредит. Резервы прерванного процесса старше двух минут освобождаются при следующем обращении к студии; старые использованные кредиты сохраняются.
- Клиент хранит ключ повторного запроса в sessionStorage вместе с хешем параметров, без текста анкеты. Потерянный ответ trial/week-plan можно получить повторно без второй генерации/дублирования. При выполняющемся запросе сервер возвращает 409; повтор нужно сделать позже. После полученного успеха следующее сознательное создание является новой операцией.
- Ручная правка запланированного текста снимает дату и согласование. ИИ-правка также начинается с возврата в черновики. Старое намерение «опубликовать сейчас» очищается при возврате и переносе.
- Согласование сверяет показанный пользователю текст, настроенный интервал (минимум 20 минут), календарный и скользящий 24-часовой бюджеты действий конкретного профиля. Части цепочки считаются отдельными действиями, как у worker. Защитные проверки worker продолжают действовать; точное время отправки не гарантируется.
- Все временные поля PostingTaskRead сериализуются с UTC, включая даты, прочитанные из SQLite без timezone. Браузер корректно переводит их в местное время.
- Фоновое обновление очереди сохраняет открытые редакторы. Ответ недельной генерации предыдущего проекта не обновляет новый проект. После сохранения согласованный пост виден в черновиках.
- Ручная генерация резервирует операцию короткой транзакцией, не удерживает SQLite write lock во время ИИ. Таймаут 120 секунд, зависшая операция восстанавливается при следующем запуске через три минуты. Удалённый во время генерации проект не получает пост без владельца; сырая ошибка провайдера не сохраняется для пользователя.
- Уточнены подсказки кабинета: сначала черновик, затем подключение профиля и согласование. Дополнены цвета новых блоков в тёмной теме.

## Новая функция из плана

Помощник описания проекта задаёт три вопроса: что предлагаете, кому и какую проблему решаете. Возвращает редактируемые description, target_audience, product_context; перенос в форму по явной кнопке, сохранение только при создании проекта. Общий стиль не изменяется. Если ничего не продают, product_context описывает пользу контента.

POST /api/v1/project-context/preview требует авторизацию и подписку, 3/minute и 20/day, одну генерацию на пользователя и две на процесс. Таймаут 40 секунд, провайдер 35 секунд, retries=0. Вход по5–1000 символов, выход strict JSON с ограниченными строками. Ответы не пишутся в БД; передаются существующему AI-провайдеру. Аналитика project_context_started/generated/applied передаёт только названия событий при согласии, без анкеты. Ограничитель и user-lock остаются process-local при текущем одном production worker.

## Проверки

19 целевых серверных проверок (12 новых и 7 регрессий контентного пути), все прошли. Сборка frontend, изолированная миграция a9b0c1d2e3f4 → b0c1d2e3f4a5 с сохранением legacy quota. Локальная UI-проверка с SQLite в памяти, отключённым lifespan/планировщиком и фикстурой ИИ: бесплатный черновик, предпросмотр/перенос контекста без создания проекта, сохранность несохранённого текста при генерации плана. Реальные клиентские профили не использованы для тестовых публикаций.

## Осталось в плане

- Цели новых событий в кабинете Метрики: код отправки есть, конфигурацию отчётов нужно сделать в доступном рекламно-аналитическом кабинете.

- Тест общего прокси-пула требует тестовый доступ; пакеты не покупались, рабочие аккаунты не переводились.
- Реклама требует согласованного лимита расходов и готового кабинета. Юридические вопросы размещения персональных данных не решаются этой технической выкладкой.
